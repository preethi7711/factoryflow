----------------------------------------------------
HOW TO RESET THE DATA (do this before every new attempt)
----------------------------------------------------

Your demo data got mixed up from previous tries? Reset it like this:

--- ON THE LIVE SITE (Render + Neon) ---

Step 1: Go to https://neon.tech  → sign in → open your FactoryFlow project
Step 2: Click "SQL Editor" in the left sidebar
Step 3: Copy ALL the contents of the file  docs/reset_db.sql
        and paste it into the SQL editor, then click Run
Step 4: Go to https://dashboard.render.com → find your FactoryFlow service
Step 5: Click "Manual Deploy" → "Deploy latest commit"
        (this restarts the service, which re-seeds the database automatically)
Step 6: Wait about 60 seconds for the site to wake up, then verify:
        Open the site → log in as admin → Orders page should be empty

--- ON LOCAL DOCKER ---

Run these commands one by one:

  docker compose exec db psql -U factoryflow factoryflow -c "DROP SCHEMA public CASCADE; CREATE SCHEMA public;"
  docker compose exec api alembic upgrade head
  docker compose exec api python -m app.seed

That wipes everything and re-seeds from scratch.

====================================================
STEP 1 — RECORD A PURCHASE  (0:30 to 1:00)
====================================================

LOGIN: production / factoryflow-demo

WHAT TO DO:
1. Go to the Production page.
2. Find the "Record a Purchase" card (bottom right area).
3. Fill in:
   - Supplier:  Flour Supplier
   - Item:      FLOUR
   - Quantity:  60   (unit: kg)
   - Rate:      45   (rupees per kg)
4. Click "Record Purchase".

YOU SHOULD SEE: "Purchase #1 posted — ₹2,700.00 before tax"

SAY:
"We bought 60 kg of flour at ₹45 per kg. The system now has
160 kg total — 100 kg opening stock plus this new purchase.
The average cost per kg automatically updates to ₹43.125.
That is the number that will flow into our production cost later."


====================================================
STEPS 2 & 3 — START AND COMPLETE A PRODUCTION RUN  (1:00 to 2:30)
====================================================

LOGIN: production (same tab, stay logged in)

WHAT TO DO (Part 1 — Start the run):
1. On the same Production page, find the left card for starting a run.
2. Recipe: MURUKKU200 (BOM-001)
3. Batches: 1
4. The planned quantities fill in automatically:
   flour 40 kg, oil 10 L, spice 1.2 kg
5. Change oil to: 10.5  (we used slightly more oil than planned)
6. Click "Start run".

YOU SHOULD SEE: "Run RUN-0001 started"

WHAT TO DO (Part 2 — Complete the run):
1. Fill in actual output:
   - Good output (packets made): 188
   - Pouches used:               194
   - Damaged pouches:              6
   - Cartons used:                 9
2. Click "Complete run".

YOU SHOULD SEE a variance table. Read these numbers out loud:
   - Yield:   -6.00%  — FLAGGED   (made 188, planned 200)
   - Oil:     +5.00%  — FLAGGED   (used 10.5 L, planned 10 L)
   - Pouches: -3.00%  — NOT flagged  (exactly at the 3% limit, not over it)

SAY:
"The variances are calculated automatically — the system reads
the actual amounts straight from the stock ledger, so the
variance screen and the stock balance can never show different numbers.
Oil is 5% over — flagged. Yield is 6% down — flagged.
Pouches are exactly at 3% — the rule says flag only when strictly
over 3%, so this one is not flagged. That is a deliberate design decision."

STEP 4 — SALESMAN PLACES AN ORDER  (2:30 to 3:15)
====================================================

LOGIN: salesman_a / factoryflow-demo  (use the PHONE window)

WHAT TO DO:
1. Switch to the phone-sized window.

3. Tap the customer card: Retailer A (Tamil Nadu).

The system makes sure the same order is never recorded twice,

====================================================
STEP 5 — APPROVE, MAKE INVOICE, DISPATCH  (3:15 to 4:30)
====================================================

LOGIN: admin / factoryflow-demo  (desktop window)

WHAT TO DO:
1. Go to the Orders tab.
2. Find the Retailer A order (status: PENDING).
3. Click "Approve" — status changes to APPROVED.
4. Click "Invoice".

YOU SHOULD SEE:
   Invoice number:  FF/2026-27/0001
   Amount:          ₹7,500 taxable
                  + ₹187.50 CGST
                  + ₹187.50 SGST
                  = ₹7,875 total

5. Click "Invoice PDF" — the PDF opens in a new tab.
   POINT AT: invoice number, GSTIN, HSN code 2106,
             "Place of supply: 33 — Tamil Nadu", CGST + SGST.
6. Close the PDF, then click "Dispatch".

YOU SHOULD SEE: Finished goods drop from 238 to 88 packets.

SAY:
"Both the factory and the customer are in Tamil Nadu — same state —
so it is CGST plus SGST, each at 2.5%.
The invoice number is auto-generated and can never have a gap.
Two people invoicing at the same time will never get the same number.
When I click Dispatch, the stock ledger records the movement
and finished goods go from 238 down to 88."


====================================================
STEP 6 — DISTRIBUTOR B: NOT ENOUGH STOCK  (4:30 to 5:00)
====================================================

PHONE WINDOW: Log out of salesman_a, log in as salesman_b
              Customer: Distributor B (Karnataka)
              Order: 120 packets → Place order

DESKTOP WINDOW (admin):
1. Go to Orders tab.
2. Find the Distributor B order (PENDING).
3. Click "Approve".

YOU SHOULD SEE an error:
   "Short by 32 — want 120, have 88"
   Tax preview: IGST ₹300, total ₹6,300

SAY:
"Only 88 packets are available, so the system blocks the approval
and shows exactly how many are short.
Distributor B is in Karnataka — a different state from the factory —
so it automatically switches to IGST instead of CGST + SGST.
The admin can approve a partial order of 88,
or hold it and schedule another production run."


====================================================
STEP 7 — RECORD A PAYMENT  (5:00 to 5:20)
====================================================

LOGIN: admin (same tab — do NOT reload)

WHAT TO DO:
1. Go back to the Retailer A order (status: DISPATCHED).
2. In the payment amount box, type: 4000
3. Click "Record payment".

YOU SHOULD SEE:
   "Recorded ₹4,000 against FF/2026-27/0001"
   Outstanding balance: ₹3,875.00

SAY:
"Invoice was ₹7,875. Customer paid ₹4,000.
Outstanding is ₹3,875.
The outstanding amount is always calculated on the fly —
it is never stored separately — so it can never go out of sync."


====================================================
STEP 8 — ADD OVERHEADS, SEE COST PER PACKET  (5:20 to 6:10)
====================================================

LOGIN: production / factoryflow-demo  (or switch back)

WHAT TO DO:
1. Go to the Production page — the completed run RUN-0001 is shown.
2. In the Overheads card:
   - Labour:    1200
   - Gas/power:  600
3. Click "Save".

YOU SHOULD SEE the cost breakdown update:
   Materials:        ₹4,055
   Overheads:        ₹1,800
   Total:            ₹5,855
   Per packet:       ₹31.14
   Margin:           ₹18.86  (37.7% at ₹50 selling price)

SAY:
"Materials cost ₹4,055. Flour is calculated at the weighted average
cost after this morning's purchase — ₹43.125 per kg — so 40 kg is ₹1,725.
The 6 damaged pouches are charged to this run as a normal production loss.
Add ₹1,800 overheads, divide by 188 good packets — cost is ₹31.14 per packet.
Selling price is ₹50, so margin is 37.7%."


====================================================
STEP 9 — MONTH-END REPORTS  (6:10 to 7:10)
====================================================

LOGIN: accountant / factoryflow-demo

WHAT TO DO:
1. Set the date range: 2026-11-01 to 2026-11-30
2. Click Refresh.
3. Click through each report tab and show these numbers:

   STOCK SUMMARY:
     Flour:          120 kg
     Oil:            19.5 L
     Pouches:        306 pcs
     Finished goods:  88 packets

   SALES REGISTER:
     One row — FF/2026-27/0001, Retailer A, ₹7,500 taxable, ₹7,875 total

   GST SUMMARY:
     ₹7,500 taxable · ₹187.50 CGST · ₹187.50 SGST
     (This is the GSTR-3B 3.1a format)

   AGEING:
     Retailer A — 0 to 30 days — ₹3,875 outstanding

   LEDGER:
     Scroll through to show: OPENING → PURCHASE → ISSUE → OUTPUT → DISPATCH
     Each row links to the document that caused it.

4. Click CSV next to the Sales Register — a CSV file downloads.

SAY:
"Every number here comes directly from summing the stock movement ledger.
There is no separate balance that someone could accidentally overwrite.
Opening stock plus receipts minus issues plus or minus adjustments
always equals the closing balance — by design, not by luck.
The accountant can download any report as CSV or Excel,
and the numbers are exactly the same as what is shown on screen."
